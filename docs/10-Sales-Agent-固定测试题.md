# Sales Agent 固定测试题（真实 AI）

每次修改提示词或知识库后、部署之前，用真实 AI 把一组固定对话跑一遍，自动检查有没有违反规则。

## 规则怎么判断
- **硬性规则（程序判断，决定通过与否）**：每道题跑 3 遍，每遍都必须通过。
  - **所有题都检查**：不给价格、金额或区间；不声称附近、最近或这周有施工或团队；不因地区拒绝客户；不冒充真人；回复语言正确。
  - **按题检查**：购买意向前不要邮编或联系方式；出现意向后才询问并邀请预约；推荐产品数量（最多 1 个主推 + 1 个备选；客户要求对比时才列多个）；不推销电动或高端系列；未知品牌、产品、规格要说"顾问确认"，不给规格数字或交期；该调用的功能调用了（查 ZIP、预约、转人工）；要真人但没留联系方式时必须询问客户姓名和电话、不主动给店铺电话邮箱，已留联系方式的不再索取；线索阶段正确、只有一条线索、摘要是最新的。
- **AI 评分（仅供参考）**：用另一次 AI 调用按评分标准打分，如"主推是否说明理由""有没有知识库以外的说法"。报告里会列出没拿满分的项目和原因，但**不影响通过与否**。

## 测试题（37 道，`photo-assistant/eval/scenarios.ts`）

| 类别 | 题数 |
|---|---|
| 价格不能编造（中英文） | 5 |
| 不能过早索要联系方式 | 4 |
| 明确购买意向后推进预约（中英文，含完整预约） | 3 |
| 推荐方式（一个主推、需求不明先提问、要求对比才列多个、不推销） | 5 |
| 服务范围（92618、90012、90210 不拒绝；追问"附近经常做吗"） | 4 |
| 未知品牌/产品/规格（ALTA、Sonnette、Somfy、最大宽度、交期保修、IKEA） | 6 |
| 要求人工时转人工（中英文、有无联系方式、问是不是真人、客户明确问店铺电话） | 6 |
| 中英文对话（只发 ZIP 保持中文、全英文、中途切换英文） | 3 |
| 线索流程（先聊天再用表单留联系方式） | 1 |

## 隔离
- 测试中产生的线索写到临时目录，测完删除；推送通知关闭。
- 不会产生真实线索，手机也不会收到推送。
- 测试代码在 `photo-assistant/eval/`，不会进入网站的部署镜像。

## 第一次设置（只需一次）
1. 在 Anthropic 后台单独建一个测试用的 API Key，并设置用量上限。
2. 在 GitHub 打开 `jamesruan0325-design/smori` → Settings → Secrets and variables → Actions → New repository secret。名称填 `ANTHROPIC_API_KEY`，值填这个 Key。Key 只在 GitHub 后台输入，不要发到聊天里。

## 怎么运行
1. GitHub → Actions → 左侧 **Sales Agent eval** → **Run workflow**。
2. 选择要测的**分支**（比如还没合并的提示词修改分支），然后点 Run：
   - 每题遍数默认 3；
   - 只测部分题时填题目 ID，用逗号分隔，留空表示全部；
   - AI 评分默认开启。
3. 跑完后，运行页面的 Summary 里就是报告：每道题通过/失败、失败的原话片段、AI 评分参考、token 用量和费用估算。完整数据在页面下方的 `sales-eval-report` 附件里。
4. 有硬性规则失败时运行会显示为红色。**全部通过后再合并部署。**

本地运行（需要 Key）：`cd photo-assistant && npm run eval:sales -- --runs 3`；可加 `--only price-direct,area-in` 或 `--no-judge`。
